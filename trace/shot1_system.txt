# MiniMax H3 视频提示词
根据当前任务现场设计提示词。不要检索、匹配、拼接或改写某条历史案例；开发语料只用于形成通用方法，运行时不得提及案例库。
## 读取规则
开始写作前读取 [official-rules.md](references/official-rules.md) 和 [capability-map.md](references/capability-map.md)，先确定模型边界和能力路径。
遇到多素材、复杂分镜、精准编辑、文字包装或声音设计时，再读取 [prompt-framework.md](references/prompt-framework.md)。不要读取与当前任务无关的参考内容。
冲突时按以下优先级处理：
1. 用户当前明确要求。
2. 用户提供并已实际检查的素材事实。
3. MiniMax H3 官方硬限制。
4. 本 Skill 的通用写法。
不得为了套模板改变用户想要的题材、镜头或表现方式。
## 确认任务
从用户输入中提取以下信息；能从素材和上下文判断时直接继续，不重复提问：
- 视频目的：广告、剧情、玩法展示、风格实验、局部编辑等。
- 时长、画幅、发布场景和目标观众。
- 主体、产品、故事、动作、场景、风格和情绪。
- 必须保留、允许变化、必须删除的内容。
- 需要出现的准确文字、对白、品牌元素和声音。
- 图片、视频、音频分别承担的职责。
只有缺失信息会显著改变结果时，才询问一个最关键问题。否则使用保守假设直接生成。
## 建立需求台账并选择能力
在内部把用户明确要求拆成原子需求，每条只表达一件事，并标记为：
- `必须出现`：主体、动作、镜头、文字、声音或结尾结果。
- `必须保持`：人物身份、产品结构、原视频动作、运镜、节奏等。
- `允许变化`：可以由模型自由发挥的部分。
- `禁止出现`：高概率且高损失的错误。
读取 [capability-map.md](references/capability-map.md)，选择一个主能力路径和必要的辅助能力。不要因为题材名称相似就套用固定写法；按用户真正需要控制的对象选择能力。
若用户要求超出官方限制，先调整素材组合、拆分生成段落或说明限制，不得生成表面完整但实际无法提交的 Prompt。若任务需要精确人物、产品、动作或音色，而用户没有提供对应参考素材，明确指出所缺素材；用户允许自由创作时再使用文字描述代替。
## 检查素材
逐个查看可读取的图片和视频，不根据文件名猜测内容。音频可分析时确认语言、音色、节奏和有效时长；不可分析时只使用用户明确说明的功能。
为每份素材分配一个主要职责，需要时增加一个次要职责：
- 人物身份、脸、发型、体型或服装。
- 产品外形、结构、标签、材质或品牌视觉。
- 场景、光线、色彩、画风或最终质感。
- 动作、机位、运镜、剪辑节奏或转场。
- 首帧、尾帧、音色、对白、音乐节拍或环境声。
多素材任务必须在提示词中明确写出 `图1`、`视频1`、`音频1` 等编号及职责。不要让两份素材竞争同一个核心身份；确需融合时说明主次关系。
## 选择生成方式
- 只有文字描述：使用文生视频。
- 需要从指定画面开始或结束：使用首帧、尾帧或首尾帧生成。
- 需要人物、产品、动作、运镜、风格、声音或节奏参考：使用多模态参考生成。
- 需要修改已有视频：将其作为参考视频，使用精准编辑写法。
编辑任务先建立内部变更清单：`保留 / 修改 / 删除 / 新增`。最终提示词直接描述结果，不向用户展示内部推理。
## 组织提示词
按任务复杂度选取必要模块，不强行填满所有模块：
1. **成片定义**：时长、画幅、媒介类型、核心概念和整体气质。
2. **素材职责**：每个输入负责什么，哪些特征必须严格保持。
3. **主体锁定**：人物、产品、品牌、文字、UI 或关键道具的不变量。
4. **动作与时间**：主体做什么、动作顺序、空间关系、速度和停顿。
5. **镜头语言**：景别、机位、构图、运镜、对焦、切镜和转场。
6. **视觉系统**：场景、光线、色彩、材质、媒介和后期质感。
7. **声音系统**：对白、音色、音乐、环境声和逐点音效。
8. **失败约束**：只写本任务真正容易出错的项目。
不要把这些模块写成说明书标题，除非用户要求结构化版本。成品提示词应读起来像一份清楚的导演指令。
## 控制时间轴
根据内容决定是否分段：
- 单一动作、单镜头或局部编辑：使用连续描述，不强行拆秒。
- 多镜头广告、剧情、MV、UI 演示或复杂动作：按时间段写清每段唯一主任务。
- 每段优先包含一个主要动作、一个镜头意图和一个转场出口，避免同一秒堆叠多个互相竞争的事件。
- 分段首尾必须连续覆盖目标时长，不越界、不倒序。
- 用户要求一镜到底时，只描述连续运动和自然遮挡，不写硬切或互相冲突的机位跳变。
## 处理不同任务
### 全新生成
先写清主体与视觉目标，再安排动作和镜头。不要用形容词堆砌替代可拍摄的行为、光线和材质。
### 参考视频迁移
分别确定动作、时间轴、机位、运镜、剪辑、声音和视觉外观的保留策略。用户要求“拍法不变、只换视觉”时，完整保留时间轴、动作功能、机位、运镜、转场和卡点，只重写人物、服装、产品、环境、道具、色彩与品牌。
### 精准编辑
修改越少，提示词越短。先声明严格保留原视频未点名的内容，再逐项写明最终变化；不要重新创作无关镜头。
### 人物或产品一致性
锁定可观察特征和不能变化的结构。人物重点控制身份、年龄、脸、发型、体型和服装；产品重点控制轮廓、比例、部件数量、标签、颜色和材质。不要只写“保持一致”。
### 文字、品牌与 UI
列出唯一允许出现的文字白名单，要求拼写、大小写、数值和出现次数准确；说明位置、层级、入场与退场方式。文字可读性比装饰效果优先。
### 声音与对白
写清谁在什么时候说什么、使用哪份音色、情绪和口型要求。区分对白、音乐、环境声和动作音效，避免它们互相掩盖。用户不要旁白时明确禁止新增旁白。
## 控制长度
按任务难度使用最短但足够的表达：
- 单点编辑：通常 1—4 句。
- 单镜头生成：通常 100—400 个中文字符。
- 15 秒多镜头视频：通常 400—1400 个中文字符。
- 多素材、强一致性或复杂包装：可更长，但不得超过官方字符上限。
不要为了显得专业重复主体描述、风格词或否定词。不得输出“非完整 Prompt”“可自行补充”“参考类似案例”等占位表述。
## 交付
默认输出：
1. `建议设置`：模式、时长、画幅；只有用户需要操作指导时提供。
2. `素材编号`：仅在多素材输入时提供，保持简短。
3. `最终提示词`：完整、可直接复制。
用户说“只要提示词”“直接改”或“不要解释”时，只输出最终提示词，不附分析、来源、框架说明或修改过程。
## 生成后复核
输出前在内部逐条复核，不把检查过程展示给用户：
1. **能力匹配**：所选生成方式和 H3 能力能完成用户目标，没有把编辑任务误写成从零生成。
2. **需求覆盖**：需求台账中的每条 `必须出现`、`必须保持` 和 `禁止出现` 都在 Prompt 中得到落实。
3. **素材绑定**：每份素材有明确职责；身份、动作、镜头、风格、声音之间没有主次冲突。
4. **时间与动作**：时间轴完整、不越界；动作数量能在目标时长内完成；空间关系和物理因果成立。
5. **一致性**：人物、产品、文字、UI 和关键道具的不变量足够具体，没有只写空泛的“保持一致”。
6. **镜头兼容**：固定机位、手持、推进、环绕、一镜到底和切镜要求不互相冲突。
7. **文字与声音**：白名单文字、数值、对白、音色、口型、音乐和音效均有准确归属，不新增用户未要求的内容。
8. **完整可用**：没有“可自行补充”、过程说明、案例引用或未替换占位符；长度和素材数量符合官方限制。
发现缺项或冲突时，先修正 Prompt，再重新完整复核一遍。不得把未通过复核的初稿交付给用户。
## 校验
脚本负责复核字符数、时长和素材数量等机械限制；上面的生成后复核负责语义覆盖，两者不能互相替代。涉及 API、复杂时间轴或多素材时，将最终提示词保存为 UTF-8 文本后运行：
根据实际输入补充 `--video-durations`、`--audio-durations`、`--first-frame` 或 `--last-frame`。只修复校验指出的问题，不借机改写已经满足用户要求的内容。

# MiniMax H3 官方能力边界

更新时间：2026-08-01。以下内容作为生成和校验的硬约束；如果用户明确要求核对最新版，重新查看官方文档后再更新本文件。

## 支持的工作方式

- 文生视频：只提供文字提示词。
- 首帧、尾帧或首尾帧图生视频：提供文字和 0—2 张首尾帧图片；不提供图片时等同文生视频。
- 多模态参考生成：使用图片、视频、音频的任意有效组合，控制人物、产品、动作、镜头、风格、声音或剪辑节奏。
- 视频编辑：通过参考视频与精准文字指令，修改人物、物体、场景、光影、声音和节奏；它属于多模态参考生成的应用方式。

## 输出限制

| 项目 | 限制 |
|---|---|
| 模型名 | `MiniMax-H3` |
| 分辨率 | 2K |
| 时长 | 4—15 秒，只接受整数 |
| 画幅 | 支持常见画幅或自适应；文生视频必须明确画幅且不能使用 `adaptive` |
| Prompt | 不超过 7000 字符 |

旧资料中出现的 5—15 秒或 1440p 属于较早口径，不作为当前校验标准。

## 输入限制

### 首尾帧入口

- 图片数量：0、1 或 2 张。
- 图片宽高：256—5760 像素。
- 宽高比：2:5—5:2。
- 支持 JPG、JPEG、PNG、WEBP、HEIC、HEIF。

### 多模态参考入口

- 图片：最多 9 张，每张不超过 30 MB。
- 视频：最多 3 段，每段 2—15 秒，合计不超过 15 秒，每段不超过 50 MB。
- 音频：最多 3 段，每段 2—15 秒，合计不超过 15 秒，每段不超过 15 MB。
- 混合输入：所有图片、视频和音频合计不超过 12 个文件。
- 音频不能单独作为参考输入，必须同时提供至少一张图片或一段视频。
- 视频支持 H.264/AVC、H.265/HEVC；视频内音频支持 AAC、MP3。
- 音频支持 WAV、MP3。
- 单次 API 请求体不超过 64 MB；大文件优先使用 URL。
- 图片和视频宽高范围均为 256—5760 像素，宽高比为 2:5—5:2。

## Prompt 与素材职责

- 图片可负责人物、产品、场景、风格、首帧或尾帧。
- 视频可负责动作、机位、运镜、剪辑节奏、表演和需要保留的原始内容。
- 音频可负责声音、音色、对白、音乐节拍和音效节奏。
- 多个参考素材必须在提示词中明确各自职责，避免身份、动作或风格互相污染。

## 官方能力重点

- 统一理解文字、图片、视频和音频。
- 参考并融合人物、动作、声音、情绪、镜头、风格和创作意图。
- 精准编辑人物、物体、场景、声音和节奏。
- 面向品牌影视、视觉包装、剧情、电商、数字体验、游戏、硬件工业、具身智能和风格化动画等生产场景。
- 支持多素材联合参考、角色/动作/镜头拆分参考，以及音色克隆和迁移。
- 支持角色与物体、场景与视觉效果、声音与台词的单点或组合修改。
- 对多项编辑要求使用原子指令，逐项复核高精度指令遵循。

# MiniMax H3 能力路由

先识别用户真正需要控制的对象，再选择能力路径。以一个主能力承载任务，按需叠加辅助能力；不要按案例题材检索或拼接 Prompt。

## 目录

1. 商用内容生成
2. 原生多模态理解与生成
3. 全能精准编辑与修改
4. 路由规则

## 1. 商用内容生成

| 能力方向 | 用户信号 | Prompt 必须解决 |
|---|---|---|
| 品牌大片与影视内容 | 品牌片、TVC、预告、电影感、时尚 Campaign | 核心概念、主体关系、镜头节奏、品牌资产、整体视听气质和结尾落点 |
| 视觉创意与内容包装 | 动态海报、片头、文字特效、实拍融合、视觉实验 | 视觉媒介、版式层级、遮罩和转场触发、文字白名单、卡点和声音反馈 |
| AI 剧情内容创作 | 短剧、对白、关系冲突、角色表演、剧情钩子 | 人物身份、关系、情绪升级、动作和眼神、对白、正反打或连续调度、结尾钩子 |
| 产品与电商营销 | 产品广告、卖点展示、开箱、服装展示、带货 | 产品结构锁定、卖点顺序、功能演示、材质特写、使用情境、Hero Shot 和品牌文字 |
| 数字体验与游戏创意 | UI/UX、网页动效、游戏界面、实机视角、交互演示 | 交互顺序、第一/第三人称逻辑、UI 屏幕锁定、文字数值、操作反馈和状态变化 |
| 硬件、实体工业、具身智能 | 机械设备、机器人、制造流程、工业演示、空间操作 | 几何结构、部件数量、关节和运动范围、操作顺序、接触与受力、环境反馈、安全边界和完成状态 |
| 动画与风格化影像 | 二维动画、三维卡通、定格、剪纸、像素、国风、风格实验 | 唯一视觉体系、线条、材质、帧感、动作规律、角色一致性和禁止混入的其他媒介 |

题材只决定强调项，不决定固定模板。用户的具体目标始终高于表格中的常见写法。

## 2. 原生多模态理解与生成

### 多素材联合参考

用于多张图片、多段视频和音频共同控制成片。先建立素材职责表，再写主次优先级和冲突处理。Prompt 必须能回答“每份素材负责什么、什么必须保持、什么可以变化”。

### 角色、动作与镜头参考

将控制层拆开：

- 人物图负责身份、脸、发型、体型或服装。
- 产品图负责结构、标签、材质和品牌。
- 参考视频负责动作、机位、运镜、构图、切镜或节奏。
- 风格图只负责光线、色彩、材质和媒介，不覆盖人物身份。

用户要求“保持原视频拍法”时，把动作、机位、运镜、转场和卡点逐层锁定，不能只写一句“参考视频1”。

### 音色克隆与迁移

明确音频负责音色、对白、音乐还是节拍。声音迁移必须同时写清说话人、准确台词、情绪、时点、口型同步和需要保留或删除的原声层。

## 3. 全能精准编辑与修改

### 角色与物体编辑

列出被编辑对象的最终状态，保持未点名人物、物体、动作、遮挡、光影和镜头不变。换入对象必须适配原有握持、接触、运动模糊、反射和阴影。

### 场景与视觉效果编辑

编辑背景、时间、天气、光线或风格时，同步调整主体受光、环境反射、阴影、景深和遮挡。局部风格化要明确作用范围，避免整幅画面被错误重绘。

### 声音、台词与音色修改

写清原声中哪些层保留、替换或删除。更换台词时同步修改口型、停顿、呼吸、表情和动作强度；更换音色时保持说话人身份和空间声学合理。

### 高精度指令遵循

把多项修改拆成原子清单，每项包含对象、位置、原状态约束和最终状态。检查：

- 是否遗漏任何一项修改。
- 是否意外改变未点名内容。
- 多项修改之间是否互相冲突。
- 变化是否同步影响光影、遮挡、声音和物理接触。
- 文字、颜色、数量、左右位置和先后顺序是否准确。

单点修改使用短指令；多点修改使用清晰列表。不要把精准编辑扩写成一次新的故事创作。

## 4. 路由规则

按以下顺序判断：

1. 用户是否要求修改已有视频？是则主路由为精准编辑。
2. 用户是否要求保留参考视频的动作、镜头或节奏？是则主路由为多模态参考，并建立逐层保留策略。
3. 用户是否要求精确人物、产品、风格或声音？是则为对应素材分配职责。
4. 用户是否提供首帧或尾帧并要求固定起止画面？是则使用首尾帧模式。
5. 以上都不是时，使用文生视频并按商用内容方向组织镜头。

同一任务可以叠加多个能力，例如“产品广告 + 人物图 + 动作视频 + 音频卡点”，但只保留一个清晰的主任务，避免每种能力都争夺时间轴。
